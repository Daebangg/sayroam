# 화면 유형별 정합성 규칙

화면을 추가·수정할 때 같은 유형의 기준 화면과 공용 스타일을 사용합니다. 셸·본문 폭·제목 간격·표면·
타이포그래피·액션 위치를 공유하되 서로 다른 유형을 같은 크기로 강제하지 않습니다.
[스타일 가이드북](../STYLE_GUIDE.md)의 팔레트·아이콘·일러스트와 실제 공용 컴포넌트를 기준으로 비교합니다.

| 유형           | 기준 소유자                                                                   | 공유 규칙                                                                                            |
| -------------- | ----------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 공개 홈        | `pages/home/HomePage.tsx`                                                     | 큐비즘 해안 히어로·검색·바로가기·여행/동행/방 요약                                                   |

여행·동행·방의 목록·일정·인원·메시지는 #60의 정적 예시입니다. 인증 모달은 #72에 통합한 로그인·회원가입·비밀번호 재설정의 실제 API를 연결합니다.
화면은 실제 주소로 이동하고 언어·테마 선택은 브라우저에 저장합니다. 여행·채팅 업무 API 연결은 별도 범위입니다.
앱 바깥에 둥근 카드 프레임을 두지 않습니다. 히어로·콘텐츠 카드에는 22px 곡률을 적용하고,
404에는 같은 면 분할 계열의 황혼 일러스트를 배경 카드로 사용합니다.

배치가 달라지는 변경은 영향을 받는 대표 화면에서 잘림·겹침·스크롤·클릭 영역을 확인합니다.
모바일 배치를 바꾸면 모바일, 데스크톱 배치를 바꾸면 데스크톱을 확인하고 공통 배치를 바꾸면 양쪽을 확인합니다.
390px와 1440px는 대표 기준이며 매번 모든 폭·테마·언어 조합이나 별도 근거 양식을 강제하지 않습니다.
문구·문서만 수정하거나 기존 검사 결과가 유효하면 관련 범위만 확인하고 검사를 반복하지 않습니다.

자동 검사만으로 시각적 동일성을 보장했다고 기록하지 않습니다. 동작 줄이기·키보드 포커스를 유지하고,
새로운 업무 기능의 회귀 검사는 해당 기능 구현 범위에서 정합니다.

## 공용 UI와 자동 검사

- 카드의 공통 표면은 `components/ui/cards/Card.tsx`가 소유합니다. 여행·동행 카드와 쇼케이스가 같은 컴포넌트를 사용하며 모바일 동행 목록의 평면형 배치는 유지합니다.
- 버튼은 공용 `Button`을 사용합니다. 내비게이션·브랜드·텍스트 링크처럼 배치가 다른 버튼은 `variant="plain"`으로 의미·기본 type·ref 처리를 공유하고 기존 레이아웃 클래스를 적용합니다.
- `TextField`의 `hint`·`error`는 입력의 `aria-describedby`와 연결하고 오류에는 `aria-invalid`를 적용합니다. 실제 업무 검증과 API 오류 연결은 각 기능에서 수행합니다.
- 브랜드 보기(`/brand`)에서 기본·선택·로딩·비활성·입력 오류·긴 문구를 확인합니다. 호버는 포인터, 포커스는 Tab·Shift+Tab으로 실제 공용 컴포넌트를 조작해 비교합니다.
- `features/brand/BrandAssets.tsx`는 SayRoam 배너·아이콘·워드마크의 밝은/어두운 배경 비교와 테마별 자산을 제공합니다. 로그아웃 프로필은 익명 실루엣, 로그인 계정의 사진 없음·실패는 `coast`를 사용하며 공용 `Avatar`의 16종 미리보기와 구분합니다.
- 날짜는 공용 `DatePicker`, 인원 증감은 `NumberStepper`를 사용합니다. 여행 진입에는 내비게이션과 같은 `trips` 아이콘, 날짜 정보에는 `calendar` 아이콘을 사용합니다.
- 드롭다운은 선택 체크·오른쪽 끝 화살표·열림/닫힘 전환을 공유하고, 단축키는 `KeyboardShortcut`의 작은 키캡을 사용합니다. 토스트는 기본 3초 후 자연스럽게 사라지며 필수 입력 오류를 대신하지 않습니다.
- 툴팁·드롭다운·날짜 선택기 포털은 화면 경계를 맞추는 좌표·너비·최대 높이만 DOM 측정으로 설정합니다. 이 기하 예외의 외형·색상은 공용 CSS가 소유합니다.

`pnpm lint`는 페이지·기능·레이아웃의 직접 button/input/select/textarea, JSX 외형 스타일·문구 리터럴을 검사합니다.
`pnpm ui:check`는 `src/styles/app.css` 외 스타일 파일과 동일 CSS 규칙 안의 같은 속성·값 중복 선언을 검사합니다.
다른 값의 브라우저 대체 선언은 허용합니다. `pnpm check`에 두 검사를 포함합니다.

별칭으로 감춘 DOM, 화면 사이의 의미상 중복 CSS, 실제 색상 대비·잘림·포커스 순서까지 자동으로 보장하지 않습니다.
이 부분은 390px·1440px의 대표 화면, 밝은·어두운 테마와 긴 번역문에서 브라우저로 확인합니다.

## 페이지 상태

`components/ui/feedback/PageState.tsx`는 404·오류·로딩의 공통 외형을 소유합니다.
상태별 배경은 공용 CSS에서 연결하며 404는 `travel-dusk.jpg`, 오류는 `travel-highland.jpg`,
로딩은 `travel-horizon.jpg`를 사용합니다. 문구·버튼·스피너는 이미지에 넣지 않고 실제 UI로 유지합니다.
`pages/status/StatusPage.tsx`가 실제 오류 페이지의 문구·홈 이동·재시도를 연결하고 브랜드 페이지는
같은 공용 컴포넌트를 사용해 세 상태를 비교합니다. 미리보기를 위해 운영 라우트에 오류를 던지는 코드를 추가하지 않습니다.
`Spinner`는 상태 문구를 제공하고 모션 줄이기 설정에서 회전을 생략합니다.
