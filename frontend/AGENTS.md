# 프론트엔드 작업 규칙

프론트엔드 작업 전 [개발 컨벤션](FRONTEND.md)과 [화면 정합성 규칙](notes/page-families.md)을 읽습니다.
화면·브랜드·아이콘·일러스트 작업은 [스타일 가이드북](STYLE_GUIDE.md)의 실제 자산과 공용 UI 기준도 먼저 확인합니다.
현재 사용자 지시와 저장소 공통 규칙을 우선하며, 문서·이슈·PR은 한국어로 작성합니다.

- 이 디렉터리는 같은 저장소의 일반 디렉터리입니다. 브랜치·커밋·PR은 저장소 루트에서 관리합니다.
- React·TypeScript strict와 이 디렉터리의 Prettier 설정을 유지합니다. 기본 선언은 `type`, Props는 `XxxProps`입니다.
- API 타입은 OpenAPI 생성 결과를 사용합니다. 페이지 → 도메인 훅 → API·오류 매핑의 책임을 지킵니다.
- API 생성 결과는 `src/api/generated/schema.ts`의 타입·경로표 한 파일로 관리합니다. 일반 API는 `api.ts`의 `api.call(operationId, options)`로 호출하며 URL·메서드·인증 요구를 복제하지 않습니다. 부가 처리는 `api.ts`의 엔드포인트별 `parseResponse`·`wrap` 확장에 등록하고 핵심 응답 검증을 유지합니다.
- 로그인·복원·로그아웃은 `authSession.ts`, 갱신·CSRF·토큰 전달은 공통 기반이 소유합니다. 변경 요청과 결과 불확실 요청을 자동 반복하지 않습니다.
- 페이지가 도메인 훅을 호출합니다. 기능 컴포넌트는 상태·액션을 props로 받고 공용 UI는 도메인을 모릅니다.
- UI 추가 전 공용 UI·레이아웃·동일 화면 유형을 확인합니다. 공유 UI → 기능 조합 → 페이지 순서로 구성합니다.
- 전체 페이지는 뷰포트 폭을 사용합니다. 앱 전체를 둥근 카드로 감싸지 않으며, 개별 콘텐츠 카드·히어로·모달에만 정해진 곡률을 적용합니다.
- CSS는 `src/styles/app.css`에서 관리합니다. 외형을 JSX 인라인 스타일이나 화면별 CSS로 복제하지 않습니다.
- 사용자 문구는 `src/locales/`의 키로 관리합니다. 신규 공용 UI는 쇼케이스에 상태별 예시를 함께 추가합니다.
- 상태 소유자는 하나로 유지합니다. 전역 저장소·memo는 실제 공유·갱신 범위와 비용을 확인한 뒤 도입합니다.
- 배치·상호작용을 변경하면 영향을 받는 대표 화면을 확인합니다. 문구·문서만 바꿀 때 전체 화면·테마·언어 조합 검증을 강제하지 않습니다.
- 설치·도구 설정·의존성·잠금 파일은 이 디렉터리 안에서 관리하며 저장소 루트에 Node 도구 설정을 추가하지 않습니다.
- 코드 변경은 필요한 타입·린트·포맷 검사를 수행하고, 빌드 설정·실행 코드 변경은 빌드도 확인합니다. 통과한 검사는 관련 변경이나 실패가 없으면 반복하지 않습니다.
- 작은 정적 UI·문구 수정에 테스트 프레임워크·E2E·화면 조합 전체 검사·별도 근거 양식을 추가하지 않습니다. 중요한 동작의 회귀 검사는 해당 동작을 구현할 때 정합니다.

현재 제공된 명령과 구현 범위는 [README](README.md)를 따릅니다. 인증은 실제 로그인·회원가입·비밀번호 재설정 API와 연결하고, 여행·동행·채팅 본문과 #86 목업 탐색은 예시 데이터를 사용합니다. 화면 검증 캡처는 PR 첨부용으로 관리하고 저장소에 추가하지 않습니다. 가이드에는 재사용하는 브랜드·일러스트 자산만 연결합니다.
