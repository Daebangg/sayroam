# 실시간 연결(STOMP)

채팅방 메시지와 멤버 변화, 개인 알림을 STOMP over WebSocket으로 주고받는 계약입니다. 클라이언트는 탭(앱 인스턴스)마다 연결 하나를 열고, 그 연결 안에서 필요한 채널을 구독·해제합니다. 한 회원은 탭·기기 수만큼 연결을 가질 수 있으며 서버는 같은 회원의 연결을 회원 ID로 묶어 관리합니다.

## 연결

`/ws`로 WebSocket을 연 뒤 CONNECT 프레임의 `Authorization: Bearer <Access Token>` 헤더로 인증합니다. 토큰이 없거나 잘못됐거나, 계정이 비활성·인증 버전 불일치이면 `UNAUTHENTICATED` ERROR 프레임을 받고 연결이 닫힙니다.

연결은 토큰 만료 시각에 서버가 끊습니다. 클라이언트는 만료 전에 토큰을 갱신해 다시 연결합니다. 연결이 끊기면 그 연결의 구독은 모두 사라지므로 재연결 후 개인 큐와 열려 있던 방 채널을 다시 구독하고, 놓친 내용은 REST로 다시 조회합니다.

## 목적지

| 목적지 | 명령 | 언제 | 내용 |
| --- | --- | --- | --- |
| `/user/queue/messages` | SUBSCRIBE | 연결 직후 한 번 | 내가 보낸 메시지의 저장 결과. 같은 회원의 모든 연결로 간다 |
| `/user/queue/errors` | SUBSCRIBE | 연결 직후 한 번 | 내 전송이 실패한 이유. 보낸 연결로만 간다 |
| `/user/queue/rooms` | SUBSCRIBE | 연결 직후 한 번 | 방 멤버십 알림 |
| `/topic/rooms/{roomId}` | SUBSCRIBE | 채팅 패널을 열 때 | 방에 저장된 메시지 |
| `/topic/rooms/{roomId}/members` | SUBSCRIBE | 채팅 패널을 열 때 | 멤버 변화 신호(빈 본문). 받으면 명단을 다시 조회한다 |
| `/app/rooms/{roomId}/messages` | SEND | 메시지 전송 | `{"clientMessageId": "<UUID>", "content": "안녕"}` |

- 방 채널은 그 방에 참여 중인 회원만 구독할 수 있습니다. 아니면 `ROOM_ACCESS_DENIED` ERROR 프레임을 받고 연결이 닫힙니다.
- 방 채널은 `receipt` 헤더와 함께 구독하고, RECEIPT를 받은 뒤 명단·메시지를 조회해야 그 사이의 변화를 놓치지 않습니다. 개인 큐에는 RECEIPT를 보내지 않습니다.
- 채팅 패널을 닫을 때는 연결을 끊지 않고 그 방 채널 두 개만 UNSUBSCRIBE합니다.
- 위 목록 밖의 구독(`/queue/**` 직접 구독 포함)과 `/app/**` 밖으로의 SEND(`/topic/**`·`/queue/**`·`/user/**` 직접 전송 포함)는 `ACCESS_DENIED` ERROR 프레임을 받고 연결이 닫힙니다. 정상 클라이언트는 이 경우를 만들지 않습니다.

## 메시지 본문

방 채널과 전송 결과는 같은 형태입니다. 같은 메시지가 두 경로로 올 수 있으므로 `messageId`로 중복을 거릅니다.

```json
{"messageId": 101, "roomId": 7, "senderId": 1, "clientMessageId": "6f1c2b6e-8a57-4b7a-9d3e-2f4a1c7e9b10", "content": "안녕", "createdAt": "2026-11-07T10:00:00Z"}
```

전송 실패는 연결을 유지한 채 `/user/queue/errors`로 옵니다.

```json
{"clientMessageId": "6f1c2b6e-8a57-4b7a-9d3e-2f4a1c7e9b10", "code": "ROOM_ACCESS_DENIED", "message": "..."}
```

## 방 멤버십 알림

`/user/queue/rooms`는 `type`으로 알림 종류를 구분합니다. 새 종류가 추가될 수 있으므로 모르는 `type`은 무시합니다.

| type | 의미 | 클라이언트 처리 |
| --- | --- | --- |
| `LEFT` | 방에서 빠졌다(이 탭·다른 탭·다른 기기에서 나가기, 탈퇴) | 그 방 채널을 구독 중이면 두 채널 모두 UNSUBSCRIBE하고 화면을 정리한다. 구독하지 않은 방이면 무시한다 |

```json
{"type": "LEFT", "roomId": 7}
```

알림 뒤 5초가 지나도 그 방 채널을 구독 중인 연결은 서버가 `ROOM_ACCESS_DENIED` ERROR 프레임으로 끊습니다. 정상 클라이언트는 그 전에 구독을 해제하므로 끊기지 않습니다. 끊긴 연결이 다시 연결해 그 방을 구독하면 권한 확인에서 거부됩니다.

## 서버가 연결을 끊는 경우

ERROR 프레임의 `message` 헤더에 이유 코드가 담깁니다.

| 코드 | 경우 | 클라이언트 처리 |
| --- | --- | --- |
| `UNAUTHENTICATED` | 토큰 만료, 비밀번호 변경·전체 로그아웃·탈퇴로 로그인 무효화 | 토큰을 갱신해 다시 연결한다. 갱신이 실패하면 로그아웃한다 |
| `ROOM_ACCESS_DENIED` | 참여하지 않은 방 구독, 나간 방의 구독을 유예 시간 안에 해제하지 않음 | 다시 연결하되 그 방은 구독하지 않는다 |
| `ACCESS_DENIED` | 허용하지 않은 목적지 구독·전송 | 클라이언트 버그이므로 다시 연결하지 않고 오류를 남긴다 |

재연결은 일정 지연(백오프)을 두고 시도합니다.

## 운영 전제

내장 브로커, 접속자 명단(`SimpUserRegistry`), 만료 종료 예약과 로그인 무효화·방 나가기에 따른 종료는 모두 서버 메모리에서 동작합니다. 따라서 서버 한 대를 전제로 합니다. 여러 대로 늘릴 때는 외부 브로커와 서버 간 종료 전달을 함께 설계해야 합니다. 연결이 끊기지 못한 경우에도 Access Token 수명(최대 15분)이 지나면 만료 종료로 끊깁니다.
