# 모집별 여행 스타일

#156부터 모집의 여행 스타일은 프로필과 독립적으로 보관합니다. 나이·성별의 상호 조건은
계속 회원 프로필을 기준으로 판단하고, 스타일 비교만 해당 모집의 저장값을 사용합니다.

## 등록·수정 계약

`POST /api/companion-searches`, `PUT /api/companion-searches/{searchId}`의 기존 본문에
다음 `travelStyle` 객체를 전달합니다. 네 키가 모두 필요하며 값은 1~5의 정수입니다.

```json
{
  "travelStyle": {
    "planning": 2,
    "daily-pace": 4,
    "time-together": 2,
    "spending": 5
  }
}
```

- 신규 등록: 명시한 점수를 모집에 저장합니다. 프로필 응답이 없어도 등록할 수 있습니다.
  `travelStyle`을 생략하거나 null로 보내면 프로필의 네 응답을 한 번 복사합니다.
  이후 프로필을 수정해도 기존 모집은 바뀌지 않습니다.
- 수정: 전달한 점수는 해당 모집에만 반영합니다. 생략하거나 null이면 모집 저장값을 유지합니다.
  다른 모집과 프로필은 바뀌지 않습니다. 종료한 모집도 수정할 수 있으며 종료 상태를 유지합니다.
- 본인 목록과 등록·수정·상태 변경 응답의 `travelStyle`은 모집 저장값입니다.
- 네 응답이 완성되지 않았으면 `409 TRAVEL_STYLE_REQUIRED`, 범위 밖 점수·알 수 없는 키·
  정수가 아닌 값이면 400을 반환합니다. 불완전한 명시 입력을 프로필로 대체하지 않습니다.

## 재개와 기존 모집

V16은 네 nullable 점수 열과 전체 미설정 또는 네 점수 완성을 보장하는 CHECK 제약을 추가합니다.
기존 모집의 당시 선택값은 알 수 없으므로 현재 프로필로 일괄 채우지 않습니다.
미설정 모집은 응답의 `travelStyle`이 `{}`이며, 수정 요청에서 네 점수를 보완해야 합니다.

`PATCH /api/companion-searches/{searchId}`의 ACTIVE 전환은 해당 모집의 저장값을 검사합니다.
프로필이 비어 있어도 모집의 네 점수가 있으면 재개할 수 있습니다. 미설정이면
`409 TRAVEL_STYLE_REQUIRED`를 반환하므로 모집 수정으로 안내합니다. 활성 모집 최대 3개 제한과
여행지 유효성 검사는 유지합니다. 이미 ACTIVE인 모집에 같은 상태를 요청하면 기존처럼 성공합니다.

## 후보 조회와 비교

등록된 모집의 후보 조회는 양쪽 모집에 저장된 점수로 비교합니다. STYLE 정렬은 저장값이 있는
후보만 대상으로 하고, 같은 회원에게 여러 모집이 있으면 가장 가까운 스타일의 모집을 선택한 뒤
전체 후보를 정렬·페이지 처리합니다. 점수가 같으면 겹치는 일수·시작일·모집 ID 순입니다.
OVERLAP 정렬은 기존 기간 기준을 유지하며 선택된 모집의 저장값으로 비교 설명을 제공합니다.
점수가 없는 기존 모집은 기간순 목록에 남지만 스타일 비교값은 null입니다.

등록 전 `GET /api/companion-candidates`는 선택한 점수를 `planning`, `dailyPace`, `timeTogether`,
`spending` 쿼리로 전달할 수 있습니다. 하나라도 전달하면 네 점수가 모두 필요합니다.
모두 생략한 경우에만 프로필 응답을 기본값으로 사용합니다. 이 조회는 프로필이나 모집을 저장하지 않습니다.

백그라운드 발견은 기존처럼 여행지·기간·상호 나이·성별 조건으로 모집 조합을 찾습니다.
스타일 점수에 따른 제외 기준이나 자동 승인 규칙은 추가하지 않습니다. 스타일 수정 시에도
모집 버전과 발견 작업을 갱신합니다.

## 배포·검증

앱 실행 전 기존 절차대로 `flywayMigrate`로 V16을 적용해야 합니다. 개인 DB에는 자동 적용하지 않습니다.
백엔드 변경과 함께 프론트엔드 계약 스냅샷·생성 타입을 갱신합니다. 화면 연결은 별도 작업입니다.
프론트엔드가 선택값을 사용하려면 위 `travelStyle` 필드를 저장 요청에 포함해야 합니다.

`CompanionSearchApiIntegrationTest`, `CompanionCandidateApiIntegrationTest`는 프로필 없이 등록·재개,
모집 간 독립성, 수정·조회, 기존 미설정 모집 보완, 입력 검증과 모집별 스타일 정렬을 확인합니다.
기존 한도·백그라운드 발견 테스트도 함께 실행합니다.
